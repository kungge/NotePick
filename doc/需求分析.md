## 1. 背景与动机（Why）

### 1.1 问题陈述

在日常浏览网页时，用户经常产生"记录当下"的需求——某段话有价值、某个页面值得收藏、某个观点需要批注。现有方案存在以下痛点：

| 痛点 | 现状描述 |
|------|---------|
| **割裂** | 浏览器收藏夹只存链接，笔记软件需要切换应用，信息在"网页"和"笔记"之间断裂 |
| **易失效** | 收藏的链接可能 404、改版、删除，原文丢失 |
| **难检索** | 收藏的网页多了之后找不到，且无法按"我当时为什么收藏"检索 |
| **难整理** | 想把网页内容沉淀成自己的知识，但复制粘贴到笔记软件又丢失了来源、格式、上下文 |
| **难分享** | 想把某段精彩内容分享给朋友，截图不优雅，复制粘贴丢失排版 |

### 1.2 产品定位

**一句话定位**：一款轻量级浏览器扩展，让用户在浏览网页时随时采集、批注、管理、检索和分享网页笔记。

**核心价值主张**：
- **采得到**：选中即存 / 一键整页保存，采集成本接近零
- **留得住**：原文快照 + 来源元数据，链接失效也不丢
- **找得回**：全文搜索 + 标签 + 笔记关系，再多的笔记也能定位
- **带得走**：导入导出 + 分享，数据不绑架

### 1.3 为什么是浏览器扩展

扩展形态相比独立 App / 网页应用的优势：
- **采集即用**：用户在产生"想记录"念头的当下就能操作，无需切换上下文
- **页面上下文**：能直接访问当前页面的 DOM、URL、选区，采集精度高
- **零迁移成本**：跟随浏览器，无需额外安装重型应用

## 2. 目标与非目标

### 2.1 目标（Goals）

| # | 目标 | 衡量方式 |
|---|------|---------|
| G1 | 让用户能在 3 秒内完成一次网页内容采集（选区/整页） | 操作步骤数、采集耗时 |
| G2 | 采集的内容可脱离原网页独立存在（链接失效不丢内容） | 快照完整性 |
| G3 | 笔记可被高效检索（全文 + 标签 + 来源） | 搜索命中率、找到笔记耗时 |
| G4 | 数据可导出为通用格式，不绑架用户 | 导出格式开放性、可再导入 |
| G5 | 【假设】作为个人工具项目，优先满足自用，再考虑通用化 | — |

### 2.2 非目标（Non-goals）

明确**不做什么**，防止范围蔓延：

- ❌ **不做完整笔记编辑器**：不替代 Notion / Obsidian，笔记以"采集 + 轻批注"为主，不做富文本深度编辑
- ❌ **不做云端账号体系（MVP 阶段）**：本地优先，不引入登录/注册/服务器同步的复杂度
- ❌ **不做协作/多人编辑**：单用户工具，不做实时协作
- ❌ **不做 AI 摘要/总结（MVP 阶段）**：先做好基础采集，AI 能力作为后续探索项
- ❌ **不做跨浏览器同步**：MVP 锁定单一浏览器内核（Chromium 系），不做 Firefox/Safari 适配
- ❌ **不做付费/商业化**：个人工具项目
- ❌ **不做网页内容去广告/清洗**：尊重原页面，不做复杂的内容提取引擎

## 3. 用户与场景

### 3.1 用户画像

**【假设】** 本项目作为 my-tools 下的个人工具，主要用户为开发者本人（知识工作者）。以下画像基于该假设展开，同时考虑通用化潜力。

**画像 A：知识沉淀型（主要）**
- 身份：开发者 / 研究者 / 写作者
- 行为：经常浏览技术文档、博客、论文、资讯
- 痛点：看到好内容想存下来，但收藏夹 = 垃圾桶，存了等于没存
- 期望：能快速抓取 + 加批注 + 日后能搜回来

**画像 B：信息分享型（次要）**
- 身份：内容创作者 / 社群活跃者
- 行为：读到精彩段落想分享给朋友/粉丝
- 痛点：截图丑、复制粘贴丢格式、原文链接可能失效
- 期望：把网页片段整理成可分享的优雅卡片/链接

### 3.2 核心使用场景（User Scenarios）

| # | 场景 | 触发 | 期望结果 |
|---|------|------|---------|
| S1 | 读到一段精彩论述，想记下来 | 选中文字 | 一键保存为笔记，附带来源页、选区上下文 |
| S2 | 整篇文章有价值，想完整存档 | 在页面任意位置触发 | 保存整页内容（含排版），日后离线可读 |
| S3 | 想给某段内容加自己的批注 | 保存笔记后 | 能在该笔记上追加个人评论 |
| S4 | 三个月后想找回"之前看过的那篇关于 X 的文章" | 打开扩展 | 搜索关键词 / 标签，快速定位 |
| S5 | 想把一段精彩内容分享给朋友 | 选中内容 | 生成可分享的形式（卡片图 / 链接 / 导出文件） |
| S6 | 想把笔记迁移到其他工具 | 批量操作 | 导出为 Markdown / JSON 等通用格式 |
| S7 | 换电脑了，想把笔记带过去 | 迁移场景 | 导出 → 新设备导入 |

## 4. 竞品简析

> 以下为快速定位性分析，非深度竞品报告。完整竞品分析可在需求确认后另开文档。

| 产品 | 优势 | 不足（机会点） |
|------|------|---------------|
| **印象笔记·剪藏** | 功能成熟、生态完整 | 重、需登录、本地检索弱、导出不开放 |
| **Notion Web Clipper** | 与 Notion 深度集成 | 强依赖 Notion 账号、离线不可用、采集慢 |
| **Cubox** | 体验好、跨端同步 | 重商业化、本地数据掌控弱 |
| **MarkDownload** | 轻量、导出 Markdown 干净 | 只做导出、无笔记管理/搜索/批注 |
| **Liner / 高亮类扩展** | 高亮体验好 | 功能单一、多数需登录、数据在云端 |
| **浏览器原生收藏夹** | 零成本 | 只存链接、无内容、无检索、无批注 |

**机会点小结**：现有产品要么太重（强依赖云账号/生态），要么太轻（只做单点如导出）。**"本地优先 + 采集轻 + 管理强 + 数据开放"** 的中间地带存在空间。

## 5. 功能需求

> 优先级说明：P0 = MVP 必做；P1 = V1 应做；P2 = 后续迭代

### 5.1 功能模块总览

```
网页笔记浏览器扩展
├── F1 内容采集
│   ├── F1.1 选区采集（选中文字保存）
│   └── F1.2 整页采集（保存整个网页）
├── F2 笔记管理
│   ├── F2.1 笔记列表与查看
│   ├── F2.2 编辑与批注
│   ├── F2.3 标签与分类
│   └── F2.4 删除与回收站
├── F3 笔记搜索
│   ├── F3.1 全文搜索
│   └── F3.2 多维筛选（标签/来源/时间）
├── F4 笔记分享
│   ├── F4.1 卡片图导出
│   └── F4.2 分享链接/内容复制
└── F5 导入导出
    ├── F5.1 导出（Markdown/JSON）
    └── F5.2 导入
```

### 5.2 详细需求

#### F1.1 选区采集 — P0

**用户故事**
> 作为知识工作者，我希望在网页上选中一段文字后能一键保存为笔记，以便日后回看时连同来源上下文一起找回。

**功能描述**
- 用户在任意网页选中文字 → 通过右键菜单 / 快捷键 / 扩展按钮触发保存
- 保存内容包含：选区文本、来源页 URL、来源页标题、采集时间、选区在页面中的位置上下文（前后各 N 字）【待确认 N 值】
- 保存时支持即时添加：标签、个人批注、笔记标题（默认用选区前若干字）

**关键交互**
- 触发方式至少支持 2 种（右键菜单 + 快捷键），降低记忆成本
- 保存成功有轻量反馈（toast / 图标角标），不打断浏览

**验收要点**
- 选区为空时不可触发
- 跨域 iframe 内的选区【待确认是否支持】
- 动态加载内容（SPA）下选区不丢失

---

#### F1.2 整页采集 — P0

**用户故事**
> 作为知识工作者，我希望一键保存当前网页的完整内容，以便即使原链接失效也能离线回看。

**功能描述**
- 保存当前页面的正文内容（HTML + 文本）+ 页面元数据（URL、标题、采集时间、Favicon）
- **【待确认】** 保存形式：纯文本 / HTML 快照 / Markdown / Readability 提取的正文 —— 建议采用「Readability 正文 + 原始 HTML 快照」双存
- 支持保存整页截图（可视区域 / 完整长图）【P1】

**关键交互**
- 扩展按钮一键触发
- 保存进度反馈（整页采集可能较慢）

**验收要点**
- 采集内容应去除导航/广告/页脚等噪声（若采用 Readability）
- 登录墙 / 付费墙后的内容无法采集，需明确提示
- 超长页面（如长文/文档站）采集的完整性

---

#### F2 笔记管理 — P0/P1

##### F2.1 笔记列表与查看 — P0

**用户故事**：作为用户，我希望能集中查看所有采集的笔记，以便统一管理。

- 扩展弹窗 / 独立管理页展示笔记列表
- 列表项展示：标题、来源标题、采集时间、标签、内容预览
- 支持排序：按采集时间（默认倒序）、按标题
- 点击查看笔记详情（含来源、批注、原文）

##### F2.2 编辑与批注 — P0

**用户故事**：作为用户，我希望能给采集的内容追加个人批注，以便记录当时的想法。

- 笔记内容可编辑（采集的原文 + 个人批注分离展示）
- 批注支持纯文本【MVP】，富文本/Markdown【P2】
- 修改时间戳记录

##### F2.3 标签与分类 — P1

**用户故事**：作为用户，我希望能用标签组织笔记，以便按主题归类检索。

- 笔记可打多个标签
- 标签可创建/重命名/删除/合并
- 支持按标签筛选笔记
- **【待确认】** 是否引入"文件夹/笔记本"层级 —— 建议 MVP 仅用标签，避免双重组织体系

##### F2.4 删除与回收站 — P1

**用户故事**：作为用户，我希望能删除无用笔记，但误删后能找回。

- 删除笔记 → 进入回收站
- 回收站支持恢复 / 彻底删除
- 回收站自动清理策略（如 30 天）【待确认】

---

#### F3 笔记搜索 — P0/P1

##### F3.1 全文搜索 — P0

**用户故事**：作为用户，我希望能用关键词搜索所有笔记内容，以便快速定位。

- 搜索范围：笔记标题、内容、批注、来源标题
- 搜索结果高亮匹配词
- 支持即时搜索（输入即出结果）【P1】

##### F3.2 多维筛选 — P1

- 按标签筛选
- 按来源域名筛选
- 按时间范围筛选
- 搜索 + 筛选可组合

---

#### F4 笔记分享 — P1

##### F4.1 卡片图导出 — P1

**用户故事**：作为内容分享者，我希望能把笔记导出为美观的卡片图，以便分享到社交平台。

- 将笔记渲染为卡片图片（含内容 + 来源 + 采集者标记）
- 支持多种卡片样式模板【待确认数量】
- 导出为 PNG，可选尺寸

##### F4.2 分享链接/内容复制 — P1

- 复制笔记内容为纯文本 / Markdown
- **【待确认】** 是否生成分享链接 —— MVP 无云服务，链接方案需另议；建议 MVP 仅做"复制为 Markdown" + "卡片图"

---

#### F5 导入导出 — P1

##### F5.1 导出 — P1

**用户故事**：作为用户，我希望能把所有笔记导出为通用格式，以便迁移到其他工具或备份。

- 支持导出格式：Markdown（每条笔记一个 .md）、JSON（结构化全量）
- 支持全量导出 / 按标签导出 / 选中导出
- 导出文件包含来源元数据（frontmatter / JSON 字段）

##### F5.2 导入 — P2

- 支持导入本扩展导出的 JSON（用于迁移/恢复）
- **【待确认】** 是否支持导入其他工具格式（如印象笔记 ENEX）—— 建议 V2 再做

## 6. 非功能需求

| 维度 | 要求 |
|------|------|
| **性能** | 选区采集 < 1s 完成；整页采集 < 5s（普通页面）；搜索 1000 条笔记 < 300ms |
| **存储** | 本地存储优先（IndexedDB）；单条笔记无硬性上限；总量超过阈值时提示清理【待确认阈值】 |
| **隐私** | 默认全本地、不上传任何数据到服务器；如未来引入云同步需明确告知并获授权；遵循最小化原则不采集用户浏览历史 |
| **兼容性** | MVP 支持 Chromium 系浏览器（Chrome / Edge）；内容脚本需适配主流站点，对 SPA 友好 |
| **安全** | 扩展权限最小化；不执行远程代码；不向第三方域名发送数据 |
| **可访问性** | 键盘可操作；快捷键可配置 |
| **国际化** | 中文优先；架构上预留 i18n【P2】 |
| **可维护性** | 模块化架构，采集 / 存储 / UI / 搜索解耦 |

├── updatedAt: timestamp

## 8. 优先级与里程碑

采用 **MVP → V1 → V2** 三段式，先跑通核心闭环再迭代增强。

### MVP（最小可用版）— 跑通"采集 → 查看 → 搜索"闭环

| 功能 | 说明 |
|------|------|
| F1.1 选区采集 | 右键菜单 + 快捷键 |
| F1.2 整页采集 | 扩展按钮一键 |
| F2.1 笔记列表与查看 | 扩展管理页 |
| F2.2 编辑与批注 | 纯文本批注 |
| F3.1 全文搜索 | 基础关键词搜索 |

**MVP 验收标准**：用户能完成"选中保存 → 打开管理页查看 → 搜索找回 → 加批注"完整链路。

### V1（完善版）— 补齐管理与导出

| 功能 | 说明 |
|------|------|
| F2.3 标签与分类 | 标签体系 |
| F2.4 删除与回收站 | 软删除 + 恢复 |
| F3.2 多维筛选 | 标签/域名/时间 |
| F4.1 卡片图导出 | 分享卡片 |
| F4.2 内容复制 | Markdown 复制 |
| F5.1 导出 | Markdown + JSON |

### V2（增强版）— 探索性能力

| 功能 | 说明 |
|------|------|
| F1.2 整页长截图 | 完整页面截图 |
| F3.1 即时搜索 | 输入即出结果 |
| F5.2 导入 | 跨工具导入 |
| AI 摘要/相关推荐 | 探索项，需另立需求 |
| 云同步 | 需另立需求，涉及账号体系 |
| 跨浏览器支持 | Firefox/Safari |

## 9. 风险与开放问题

### 9.1 风险

| # | 风险 | 影响 | 应对 |
|---|------|------|------|
| R1 | 整页采集对复杂页面（SPA/登录墙/动态加载）兼容性差 | 采集内容不完整 | MVP 限定普通文章页，复杂页提示降级为链接收藏 |
| R2 | 本地存储容量受限（IndexedDB 配额） | 大量笔记后无法写入 | 监控用量、提示导出清理；V2 考虑云同步 |
| R3 | 浏览器扩展权限审核趋严 | 上架受阻 | 权限最小化、隐私政策清晰；自用可开发者模式加载 |
| R4 | 内容采集涉及版权/合规 | 分享时侵权风险 | 分享功能默认仅个人内容；提示用户遵守版权 |
| R5 | 【假设】个人项目投入有限 | 进度缓慢 | 严控 MVP 范围，先跑通闭环 |
