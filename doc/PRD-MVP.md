## 1. 决策记录（ADR）

> 需求分析阶段 10 项待确认问题，PM 裁定如下。每项含决策理由。

| 编号 | 问题 | 决策 | 理由 |
|------|------|------|------|
| D1 | 整页采集内容形式 | **Readability 正文 + 原始 HTML 快照**双存 | 正文用于阅读和搜索（干净、可索引），HTML 快照用于保真还原（防止 Readability 提取失败或丢格式）。双存是行业成熟做法 |
| D2 | 标签 vs 文件夹 | **仅标签，不引入文件夹层级** | 标签更灵活、支持多维度归类；双重组织体系增加认知负担和实现复杂度，与"轻量"定位冲突 |
| D3 | 选区上下文保留字数 | **前后各 100 字** | 100 字足够提供语义上下文判断来源段落，又不至于让笔记冗长 |
| D4 | 回收站清理周期 | **30 天**（V1 实现，MVP 仅预留 `deletedAt` 字段） | 30 天是误删恢复的合理窗口；MVP 不做回收站 UI，但数据模型预留软删除能力 |
| D5 | MVP 锁定浏览器 | **Chrome**（Chromium 内核，Edge 可兼容） | 市占率最高；Extension API 最完善；Manifest V3 支持最好；Edge 同为 Chromium 内核可低成本兼容 |
| D6 | 账号 / 云同步 | **MVP 无，全本地存储** | 本地优先降低复杂度（无账号/鉴权/服务器）；自用场景本地足够；架构上为 V2 云同步预留 |
| D7 | 分享链接方案 | **P1 功能，不在 MVP** | 无云服务无法生成可访问链接；MVP 聚焦采集-管理-搜索闭环 |
| D8 | 跨域 iframe 选区采集 | **MVP 不支持，提示用户** | 浏览器同源策略限制，跨域 iframe 内 DOM 不可直接访问；技术上需注入独立 content script 到 iframe，复杂度高，收益低 |
| D9 | 默认快捷键 | **选区采集 `Alt+S`** / **整页采集 `Alt+P`** / **打开管理页 `Alt+Shift+N`** | Alt 组合键冲突少；S=Save/P=Page/N=Notes 记忆性强；所有快捷键用户可在 `chrome://extensions/shortcuts` 自定义 |
| D10 | 后续开源 | **待定，不影响 MVP** | MVP 先满足自用；代码结构和许可证可在 V1 后再定 |

## 2. 问题陈述（Problem Statement）

知识工作者在浏览网页时频繁产生"记录当下"的需求，但现有方案存在断层：

- 浏览器收藏夹只存链接，**内容会随原页面失效而丢失**，且无法按内容检索
- 主流剪藏工具（印象笔记、Notion Clipper）**强依赖云账号和生态**，重、慢、数据不可控
- 轻量导出工具（MarkDownload）**只做单点**，无笔记管理、搜索、批注能力

**目标用户**：开发者 / 研究者 / 写作者等知识工作者（自用场景优先）。
**发生频率**：每日数次至数十次。
**不解决的代价**：有价值的网页内容随时间流失；知识无法沉淀为可检索的个人库；反复"找之前看过的那篇"浪费大量时间。

## 3. 目标与非目标

### 3.1 目标（Goals）

| # | 目标 | 衡量方式 |
|---|------|---------|
| G1 | 用户能在 **3 秒内**完成一次选区采集（从选中到保存成功反馈） | 操作耗时 |
| G2 | 用户能在 **5 秒内**完成一次整页采集（普通文章页） | 操作耗时 |
| G3 | 采集的笔记可脱离原网页独立存在，**链接失效不丢内容** | 快照完整性验证 |
| G4 | 1000 条笔记规模下，全文搜索 **< 300ms** 返回结果 | 搜索响应耗时 |
| G5 | 跑通"采集 → 查看 → 搜索 → 批注"完整闭环，每个环节无阻断 | 端到端用例通过 |

### 3.2 非目标（Non-Goals）

| 非目标 | 排除理由 |
|--------|---------|
| 不做富文本/Markdown 编辑器 | 笔记以"采集 + 纯文本批注"为主，深度编辑非核心价值 |
| 不做账号体系与云同步 | 本地优先，降低 MVP 复杂度；云同步为 V2 |
| 不做协作 / 多人编辑 | 单用户工具 |
| 不做 AI 摘要 / 智能推荐 | 先验证基础闭环价值；AI 为 V2 探索项 |
| 不做标签管理（创建/合并/重命名） | 标签管理为 V1；MVP 仅支持采集时打标签 + 按标签筛选的只读视图 |
| 不做回收站 UI | 回收站为 V1；MVP 仅预留数据层软删除字段 |
| 不做分享功能 | 分享为 V1（P1） |
| 不做导入功能 | 导入为 V2 |
| 不做跨浏览器适配 | MVP 锁定 Chrome |
| 不做跨域 iframe 采集 | 同源策略限制，复杂度高收益低 |

## 4. 用户故事（User Stories）

按优先级排序，覆盖 happy path 与边界场景。

### 核心闭环

- **US-01**：作为知识工作者，我希望在网页上选中一段文字后通过右键菜单或快捷键一键保存为笔记，以便日后连同来源上下文一起找回。
- **US-02**：作为知识工作者，我希望一键保存当前网页的完整内容，以便即使原链接失效也能离线回看。
- **US-03**：作为知识工作者，我希望在扩展管理页集中查看所有采集的笔记列表，以便统一浏览管理。
- **US-04**：作为知识工作者，我希望能点击某条笔记查看详情（含原文、来源、批注），以便回顾当时采集的内容。
- **US-05**：作为知识工作者，我希望能给采集的笔记追加个人批注，以便记录当时的想法和思考。
- **US-06**：作为知识工作者，我希望能用关键词搜索所有笔记的标题、内容和批注，以便快速定位之前采集的内容。

### 辅助场景

- **US-07**：作为知识工作者，我希望采集时能即时给笔记打标签，以便后续按主题筛选。
- **US-08**：作为知识工作者，我希望保存时有轻量的成功反馈（不弹窗打断浏览），以便确认采集成功。
- **US-09**：作为知识工作者，我希望能删除误采的笔记，以便保持笔记库整洁。（MVP 直接删除，不进回收站 UI；数据层软删除）

### 边界场景

- **US-10**：作为用户，当选区为空时触发采集，我希望得到明确提示而非静默失败。
- **US-11**：作为用户，当整页采集遇到登录墙/动态内容时，我希望得到降级提示而非保存到残缺内容。
- **US-12**：作为用户，当搜索无结果时，我希望看到空状态提示而非空白。
- **US-13**：作为用户，当笔记库为空时打开管理页，我希望看到引导提示而非空白。

## 5. 功能需求详细设计

> 优先级：P0 = MVP 必做；P1 = V1 快速跟进；P2 = 未来考虑（架构需兼容）

### 5.1 F1.1 选区采集（Selection Capture）— P0

#### 功能描述

用户在任意网页选中文字，通过**右键菜单**或**快捷键 `Alt+S`** 触发保存。系统将选区文本、来源元数据、上下文存为一条笔记，并允许即时打标签和写批注。

#### 交互流程

```
用户选中文字
   │
   ├─ 方式A：右键 → "保存为网页笔记"
   │
   └─ 方式B：按 Alt+S
        │
        ▼
  Content Script 提取选区信息
  (选区文本 / 选区HTML / 前后各100字上下文 / 页面元数据)
        │
        ▼
  发送消息 → Service Worker
        │
        ▼
  Service Worker 存入 IndexedDB
  (弹出轻量 toast：✓ 已保存 / 可点击编辑)
        │
        ▼
  Toast 自动消失（3s）或用户点击进入快速编辑
```

#### 数据采集规格

| 字段 | 来源 | 说明 |
|------|------|------|
| `content.text` | `window.getSelection().toString()` | 纯文本 |
| `content.html` | `selectionRange.cloneContents()` 序列化 | 选区原始 HTML（保留格式） |
| `source.url` | `location.href` | 去除 hash 片段 |
| `source.title` | `document.title` | 页面标题 |
| `source.domain` | `location.hostname` | 域名 |
| `source.favicon` | `link[rel="icon"]` href 或 `/favicon.ico` | 站点图标 URL |
| `source.selectionContext.before` | 选区起点前 100 字 | 上下文 |
| `source.selectionContext.after` | 选区终点后 100 字 | 上下文 |
| `title` | 选区纯文本前 30 字 | 自动生成，可编辑 |
| `createdAt` | `Date.now()` | 采集时间戳 |

#### 验收标准

- [ ] **Given** 用户在普通网页选中一段文字 **When** 右键选择"保存为网页笔记" **Then** 笔记保存成功，管理页可见该条记录，内容含选区文本和来源 URL
- [ ] **Given** 用户选中文字 **When** 按 `Alt+S` **Then** 笔记保存成功，效果同右键菜单
- [ ] **Given** 用户未选中任何文字 **When** 触发采集 **Then** 显示提示"请先选中要保存的内容"，不创建空笔记
- [ ] **Given** 采集成功 **When** 保存完成 **Then** 页面右上角显示 toast"✓ 已保存到网页笔记"，3 秒自动消失
- [ ] **Given** toast 显示中 **When** 用户点击 toast **Then** 打开快速编辑面板（可加标签/批注）
- [ ] **Given** 选区跨越多个段落/含链接/含图片 **When** 保存 **Then** 纯文本和 HTML 均正确保留
- [ ] **Given** SPA 页面（如 React/Vue 应用）动态渲染的内容 **When** 选中并保存 **Then** 选区不丢失，正常采集
- [ ] **Given** 跨域 iframe 内的文字 **When** 用户选中并触发 **Then** 显示提示"暂不支持跨域 iframe 内采集，请在主页面操作"（D8）

#### P0 / P1 拆分

- **P0**：右键菜单触发 + 快捷键触发 + 基础采集（文本/HTML/来源）+ toast 反馈
- **P1**：toast 点击进入快速编辑面板、favicon 采集、选区上下文
- **P2**：跨域 iframe 采集

### 5.2 F1.2 整页采集（Full Page Capture）— P0

#### 功能描述

用户点击**扩展图标按钮**或按快捷键 `Alt+P`，系统保存当前页面的正文内容（Readability 提取）+ 原始 HTML 快照 + 页面元数据。

#### 交互流程

```
用户在目标网页
   │
   ├─ 方式A：点击扩展图标 → 弹窗 → "保存整页"
   │
   └─ 方式B：按 Alt+P
        │
        ▼
  Content Script 获取完整 document.documentElement.outerHTML
        │
        ▼
  Service Worker 调用 Readability 提取正文
        │
        ├─ 提取成功 → 存储 {readability正文, html快照, 元数据}
        │
        └─ 提取失败 → 降级：仅存 html 快照 + 标记 extractionFailed
        │
        ▼
  toast：✓ 整页已保存（含正文 X 字）
```

#### 数据采集规格

| 字段 | 说明 |
|------|------|
| `content.text` | Readability 提取的 `textContent`（正文纯文本） |
| `content.html` | Readability 提取的 `innerHTML`（正文 HTML，已去噪） |
| `content.rawHtml` | `document.documentElement.outerHTML` 原始完整快照（保真用） |
| `content.readability` | Readability 返回的对象（title/excerpt/byline/length 等） |
| `source.url/title/domain/favicon` | 同 F1.1 |
| `extractionFailed` | boolean，Readability 是否提取失败 |

#### 验收标准

- [ ] **Given** 用户在普通文章页（博客/新闻/文档） **When** 点击扩展按钮选"保存整页" **Then** 笔记保存成功，含 Readability 正文 + HTML 快照
- [ ] **Given** 用户在普通文章页 **When** 按 `Alt+P` **Then** 直接触发整页保存（无需点按钮）
- [ ] **Given** Readability 提取成功 **When** 查看笔记 **Then** 正文为干净的文章主体（无导航/广告/侧边栏）
- [ ] **Given** Readability 提取失败（如非文章页/结构异常） **When** 保存 **Then** 降级存储原始 HTML 快照，笔记标记 `extractionFailed: true`，toast 提示"正文提取失败，已保存原始快照"
- [ ] **Given** 登录墙后的内容 **When** 尝试整页采集 **Then** 采集到的是登录页内容，toast 提示"当前页面可能需要登录，采集内容可能不完整"
- [ ] **Given** 超长页面（> 500KB HTML） **When** 保存 **Then** 正常存储，无截断；如超 IndexedDB 单条限制则提示
- [ ] **Given** 采集成功 **When** 完成 **Then** toast 显示"✓ 整页已保存（正文 X 字）"

#### P0 / P1 拆分

- **P0**：扩展按钮触发 + Readability 正文 + HTML 快照 + 降级处理 + toast 反馈
- **P1**：快捷键 `Alt+P`、字数统计显示、favicon 采集
- **P2**：整页长截图

### 5.3 F2.1 笔记列表与查看（Note List & Detail）— P0

#### 功能描述

扩展提供**独立管理页**（chrome-extension://xxx/manager.html），展示所有笔记列表，支持查看详情、排序、删除。

#### 界面结构

```
┌─────────────────────────────────────────────────┐
│  网页笔记                    [搜索框]    [设置]  │  ← 顶栏
├──────────┬──────────────────────────────────────┤
│          │  笔记列表                             │
│ 侧边栏    │  ┌────────────────────────────┐     │
│          │  │ 📄 笔记标题                  │     │
│ 全部(N)  │  │ 来源：example.com · 2小时前  │     │
│ #标签1   │  │ 内容预览前两行...            │     │
│ #标签2   │  │ #标签 #标签                  │     │
│          │  └────────────────────────────┘     │
│          │  ┌────────────────────────────┐     │
│          │  │ ...                         │     │
│          │  └────────────────────────────┘     │
└──────────┴──────────────────────────────────────┘
```

#### 列表项展示

每条笔记卡片展示：
- 标题（无标题时取内容前 30 字）
- 来源域名 + favicon + 采集时间（相对时间：刚刚/X分钟前/X小时前/X天前/日期）
- 内容预览（纯文本前 2 行，约 80 字）
- 标签（如有）
- 采集类型图标（📝选区 / 📄整页）

#### 详情视图

点击列表项 → 展开详情面板（或新开详情页）：
- 笔记标题（可编辑）
- 来源信息：页面标题（可点击跳转原 URL）、域名、采集时间
- 采集内容：
  - 选区型：选区内容（渲染 HTML）+ 上下文（灰色展示前后 100 字）
  - 整页型：Readability 正文（渲染 HTML）
- 个人批注（编辑区）
- 标签
- 操作：编辑、删除

#### 验收标准

- [ ] **Given** 笔记库有数据 **When** 打开管理页 **Then** 显示笔记列表，按采集时间倒序排列
- [ ] **Given** 笔记库为空 **When** 打开管理页 **Then** 显示空状态引导："还没有笔记，试试在网页上选中文字右键保存吧"
- [ ] **Given** 列表展示 **When** 查看列表项 **Then** 每项含标题、来源、时间、预览、标签、类型图标
- [ ] **Given** 用户点击某条笔记 **When** 打开详情 **Then** 展示完整内容、来源、批注、标签
- [ ] **Given** 详情中的来源标题 **When** 用户点击 **Then** 在新标签页打开原 URL
- [ ] **Given** 列表项 **When** 鼠标悬停 **Then** 显示删除按钮
- [ ] **Given** 用户点击删除 **When** 确认删除 **Then** 笔记从列表移除（数据层软删除，设 `deletedAt`）
- [ ] **Given** 管理页 **When** 用户切换排序方式（时间/标题） **Then** 列表重新排序（P1，MVP 默认时间倒序）

#### P0 / P1 拆分

- **P0**：列表展示 + 时间倒序 + 详情查看 + 删除（软删除）+ 空状态
- **P1**：标题排序、侧边栏标签筛选、相对时间显示优化
- **P2**：虚拟滚动（笔记量大时）

### 5.4 F2.2 编辑与批注（Edit & Annotate）— P0

#### 功能描述

用户可在笔记详情中编辑标题、追加个人批注、修改标签。采集的原文与个人批注分离展示。

#### 编辑能力

| 可编辑字段 | 类型 | 说明 |
|-----------|------|------|
| `title` | 纯文本 | 笔记标题 |
| `annotation` | 纯文本 | 个人批注（多行文本，支持换行） |
| `tags` | 标签数组 | 增删标签 |

> **约束**：采集的原文（`content`）**不可编辑**，保持采集时的原始快照。这是"采集真实性"原则——原文是事实记录，批注是个人思考。

#### 交互

- 详情页各字段支持 inline 编辑（点击即编辑）或编辑模式切换
- 批注区为空时显示占位提示"写下你的想法..."
- 标签输入支持自动补全（从已有标签中匹配）
- 保存方式：自动保存（失焦/快捷键 `Ctrl+S`）或显式保存按钮

#### 验收标准

- [ ] **Given** 用户打开笔记详情 **When** 点击标题 **Then** 进入标题编辑态，修改后失焦自动保存
- [ ] **Given** 详情页批注区 **When** 用户输入批注文字 **Then** 文字保存到 `annotation` 字段
- [ ] **Given** 批注区为空 **When** 查看详情 **Then** 显示占位提示"写下你的想法..."
- [ ] **Given** 用户在标签输入框输入 **When** 输入已有标签的前缀 **Then** 显示自动补全建议
- [ ] **Given** 用户添加新标签（不存在） **When** 回车确认 **Then** 创建新标签并关联到笔记
- [ ] **Given** 用户编辑后 **When** 查看 `updatedAt` **Then** 更新时间戳已刷新
- [ ] **Given** 采集的原文 **When** 查看详情 **Then** 原文不可编辑（只读展示）

#### P0 / P1 拆分

- **P0**：标题编辑 + 批注（纯文本）+ 标签增删 + 自动保存
- **P1**：标签自动补全、`Ctrl+S` 显式保存、批注 Markdown 支持
- **P2**：批注富文本

### 5.5 F3.1 全文搜索（Full-text Search）— P0

#### 功能描述

管理页顶栏提供搜索框，输入关键词即时搜索笔记的标题、内容（纯文本）、批注字段，结果高亮匹配词。

#### 搜索范围

| 搜索字段 | 说明 |
|---------|------|
| `title` | 笔记标题 |
| `content.text` | 采集内容纯文本 |
| `annotation` | 个人批注 |
| `source.title` | 来源页标题 |

#### 搜索行为

- **匹配方式**：子串匹配（case-insensitive），MVP 不做分词/模糊搜索
- **结果排序**：按相关度（匹配字段优先级：标题 > 批注 > 内容 > 来源标题）+ 时间综合排序；MVP 可简化为按时间倒序
- **高亮**：搜索结果中匹配词高亮显示
- **结果展示**：复用列表卡片样式，高亮匹配词
- **清空**：清空搜索框恢复全量列表

#### 验收标准

- [ ] **Given** 用户在搜索框输入关键词 **When** 输入完成（或回车） **Then** 返回所有匹配的笔记列表
- [ ] **Given** 搜索结果 **When** 查看 **Then** 匹配词高亮显示
- [ ] **Given** 搜索无匹配结果 **When** 查看结果区 **Then** 显示空状态"未找到匹配「关键词」的笔记"
- [ ] **Given** 用户清空搜索框 **When** 搜索框为空 **Then** 恢复显示全量笔记列表
- [ ] **Given** 笔记库 1000 条 **When** 搜索 **Then** 结果在 300ms 内返回（G4）
- [ ] **Given** 搜索关键词含大小写 **When** 搜索 **Then** 大小写不敏感匹配

#### P0 / P1 拆分

- **P0**：关键词搜索（标题/内容/批注/来源标题）+ 结果高亮 + 空状态 + 清空恢复
- **P1**：即时搜索（输入即出结果，debounce 200ms）、相关度排序
- **P2**：分词搜索、模糊搜索、搜索历史

## 6. 技术方案方向

> 本节为技术方向建议，非最终技术设计。工程团队评审时可调整。

### 6.1 整体架构

采用 Chrome Extension **Manifest V3** 架构，四层结构：

```
┌─────────────────────────────────────────────────┐
│  UI 层                                           │
│  ┌──────────┐  ┌──────────────┐  ┌───────────┐ │
│  │ Popup    │  │ Manager Page │  │ Content   │ │
│  │ (弹窗)   │  │ (管理页)     │  │ Script    │ │
│  │ 采集入口  │  │ 列表/详情/   │  │ (注入页面) │ │
│  │          │  │ 搜索/编辑    │  │ 选区/整页  │ │
│  └────┬─────┘  └──────┬───────┘  │ 采集      │ │
│       │               │          └─────┬─────┘ │
├───────┼───────────────┼────────────────┼───────┤
│       └───────────────┴────────────────┘       │
│              chrome.runtime.sendMessage         │
│  Service Worker 层（后台逻辑）                   │
│  ┌──────────────────────────────────────────┐  │
│  │ 消息路由 / 采集处理 / Readability 调用     │  │
│  │ 存储读写 / 搜索 / 数据模型管理             │  │
│  └────────────────────┬─────────────────────┘  │
├───────────────────────┼─────────────────────────┤
│              存储层                              │
│              ┌────────┴────────┐                │
│              │   IndexedDB     │                │
│              │  notes / tags   │                │
│              └─────────────────┘                │
└─────────────────────────────────────────────────┘
```

**各层职责**：
- **Content Script**：注入页面，负责选区提取、整页 DOM 获取、页面元数据采集
- **Popup**：扩展图标点击后的弹窗，提供采集入口（整页保存按钮、快捷操作）
- **Manager Page**：独立管理页（全屏 tab），笔记列表/详情/搜索/编辑的主体
- **Service Worker**：后台逻辑中枢，消息路由、采集处理、Readability 调用、存储读写、搜索
- **IndexedDB**：本地持久化存储，notes 和 tags 两个 object store

### 6.2 技术选型建议

| 模块 | 选型 | 理由 |
|------|------|------|
| 扩展规范 | Manifest V3 | Chrome 推荐标准，未来兼容性 |
| UI 框架 | **【待工程评审】** Vue 3 或 React | 管理页交互较复杂，框架提升开发效率；Popup 轻量可用原生 |
| 构建工具 | Vite | 快速、MV3 友好，社区有成熟模板（如 @crxjs/vite-plugin） |
| 正文提取 | @mozilla/readability | Mozilla 官方维护，Readability.js 标准实现，成熟稳定 |
| 存储 | IndexedDB（原生 API 或 Dexie.js 封装） | 容量大、结构化；Dexie 提供友好 API，推荐 |
| 全文搜索 | MVP 用 IndexedDB index + 内存过滤；V2 考虑 lunr.js / FlexSearch | 1000 条规模原生即可；量大后引入索引库 |
| 样式 | Tailwind CSS 或 CSS Modules | 管理页样式隔离，避免污染页面 |

### 6.3 数据模型（详细）

#### Object Store: `notes`

```
Note {
  id: string              // UUID，主键
  type: 'selection' | 'page'
  title: string           // 笔记标题（可编辑）
  content: {
    text: string          // 纯文本（选区文本 / Readability textContent）
    html: string          // HTML（选区 HTML / Readability innerHTML）
    rawHtml?: string      // 仅 type=page：原始完整页面快照
    readability?: object  // 仅 type=page：Readability 返回对象
  }
  annotation: string      // 个人批注（纯文本，可编辑）
  source: {
    url: string
    title: string         // 来源页标题
    domain: string
    favicon?: string
    selectionContext?: {
      before: string      // 前 100 字（仅 type=selection）
      after: string       // 后 100 字（仅 type=selection）
    }
  }
  tags: string[]          // 标签 ID 数组（关联 tags store）
  extractionFailed?: boolean  // 仅 type=page：Readability 是否失败
  createdAt: number       // 创建时间戳
  updatedAt: number       // 更新时间戳
  deletedAt: number|null  // 软删除时间戳（MVP 预留，UI 不暴露回收站）
}
```

**索引**：
- `by_createdAt`：`createdAt`（列表排序）
- `by_type`：`type`（按类型筛选）
- `by_title`：`title`（标题搜索）
- `by_tags`：`tags`（标签筛选，multiEntry）

#### Object Store: `tags`

```
Tag {
  id: string              // UUID，主键
  name: string            // 标签名（唯一）
  color?: string          // 标签颜色（P1）
  createdAt: number
}
```

**索引**：
- `by_name`：`name`（unique，防重复）

### 6.4 关键技术点

| 技术点 | 方案 | 风险 |
|--------|------|------|
| 选区提取 | `window.getSelection()` + `Range.cloneContents()` | SPA 动态内容选区可能不稳定，需测试 |
| 整页 DOM 获取 | `document.documentElement.outerHTML` | 含动态内容可能不完整；Shadow DOM 需特殊处理 |
| Readability 调用 | 在 Service Worker 中跑（需 DOM 环境）或 Content Script 中跑后传结果 | Readability 依赖 DOM，Service Worker 无 DOM；**建议在 Content Script 中执行后将结果传给 SW 存储** |
| 存储容量 | IndexedDB 单域通常可用数百 MB~GB 级 | 监控用量，超阈值提示导出 |
| 搜索性能 | 1000 条内存加载 + 子串匹配 | 量大后需引入 FlexSearch；MVP 原生够用 |
| 消息通信 | `chrome.runtime.sendMessage` / `chrome.tabs.sendMessage` | 注意 MV3 Service Worker 生命周期（空闲会休眠） |

### 6.5 权限声明（manifest.json 关键权限）

```json
{
  "permissions": [
    "contextMenus",      // 右键菜单
    "activeTab",         // 获取当前页信息
    "storage",           // chrome.storage（配置项）
    "scripting"          // 动态注入 content script
  ],
  "host_permissions": [
    "<all_urls>"         // 在任意页面采集（用户触发时才激活）
  ]
}
```

> **权限最小化原则**：仅声明必要权限；`<all_urls>` 是采集必需，但 content script 仅在用户主动触发时执行采集逻辑，不做被动监听。

## 7. 界面与交互设计

### 7.1 关键界面

| 界面 | 触发方式 | 核心元素 |
|------|---------|---------|
| **Popup 弹窗** | 点击扩展图标 | 整页保存按钮、最近 3 条笔记快捷入口、管理页入口 |

### 7.2 状态流转

#### 笔记状态机

```
[采集创建] ──→ [活跃] ──→ [软删除] ──→ [物理删除]
  (created)    (active)   (deletedAt)   (V1回收站清理)
```

MVP 仅实现：采集创建 → 活跃 → 软删除（UI 直接删，数据层标记）。

#### 管理页视图状态

```
空状态 ──(有数据)──→ 列表视图 ──(点击项)──→ 详情视图
  ↑                   │  ↑                    │
  └──(全删)───────────┘  │                    │
                         │                    │
                    (搜索)                    │
                         ↓                    │
                    搜索结果 ──(点击项)────────┘
                         │
                    (无结果)
                         ↓
                    搜索空状态
```

### 7.3 响应式

管理页为全屏 tab，适配桌面端宽度（> 800px）；不做移动端适配（扩展本身在桌面浏览器运行）。

## 11. 风险与依赖

| # | 风险 | 影响 | 概率 | 应对 |
|---|------|------|------|------|
| R1 | Readability 对部分页面提取失败或内容残缺 | 整页采集质量下降 | 中 | 降级存储 rawHtml + 标记 `extractionFailed`；后续优化提取规则 |
